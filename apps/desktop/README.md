# WIMM Desktop

Electron + React + TanStack Query client for the WIMM personal-finance API.

## Development

```bash
pnpm install
pnpm --filter @wimm/desktop dev
```

Reads `EXPO_PUBLIC_API_URL` (or fallback in `lib/api-client.ts`) for the API
endpoint. Ship the API in parallel:

```bash
pnpm db:up                          # Postgres via docker
pnpm --filter @wimm/api dev         # Nest API
```

## Building installers locally

```bash
pnpm --filter @wimm/desktop package
```

Outputs to `apps/desktop/release/`:

- `Wimm-x.y.z.dmg` and `Wimm-x.y.z-mac.zip` (macOS, arm64 by default on Apple Silicon)
- `Wimm Setup x.y.z.exe` and `Wimm-x.y.z-win.zip` (Windows; only when run on Windows)
- `Wimm-x.y.z.AppImage` and `wimm_x.y.z_amd64.deb` (Linux)

The CI matrix (`.github/workflows/release-desktop.yml`) builds all three
platforms on tag push (`v*`) and publishes the artifacts to GitHub Releases.

## Auto-update

The packaged app checks for new releases on launch via `electron-updater`,
pointed at this repo's GitHub Releases. When a newer version is available it
downloads in the background and surfaces a "Restart" toast.

To ship a new release:

```bash
# 1. Bump version
pnpm --filter @wimm/desktop version patch  # or minor / major

# 2. Tag and push
git tag v0.0.2
git push origin v0.0.2
```

CI builds, publishes, and active installs pick it up next launch.

## Installing on macOS / Windows (unsigned)

The desktop builds are **not code-signed** in the friends-test phase. Users
will see a security warning the first time they open the app. This is normal —
no action is required by us, just by the user.

### macOS

1. Download `Wimm-x.y.z.dmg` from the release page
2. Open the DMG, drag Wimm to Applications
3. The first launch will be blocked with "Apple cannot verify…"
4. Right-click the Wimm icon in Applications → **Open** → confirm
5. Subsequent launches work normally

When we enroll in the Apple Developer Program ($99/yr), the Mac build can be
signed and notarized — the warning goes away. (See the project plan for the
trigger.)

### Windows

1. Download `Wimm Setup x.y.z.exe` from the release page
2. Run the installer
3. Windows SmartScreen will say "Windows protected your PC"
4. Click **More info** → **Run anyway**
5. Subsequent launches work normally

Windows code-signing certificates cost $200+/yr and aren't planned for
friends-test.

### Linux

`.AppImage` is portable; just `chmod +x` and run. `.deb` installs via
`sudo dpkg -i`.

## Brand assets

Source assets in `src/renderer/assets/images/` are `337x225`. The icon used
for distribution (`build-resources/icon.{icns,ico,png}`) is generated by
padding the source to `1024x1024` with the dark theme background. To
regenerate after replacing the source:

```bash
cd apps/desktop/build-resources
sips -z 1024 1024 --padToHeightWidth 1024 1024 --padColor 0a0a0c \
  ../src/renderer/assets/images/wimm-logo-icon.png --out icon.png

# .icns (macOS)
mkdir icon.iconset
for size in 16 32 64 128 256 512 1024; do
  sips -z $size $size icon.png --out icon.iconset/icon_${size}x${size}.png
done
for size in 16 32 128 256 512; do
  doubled=$((size * 2))
  sips -z $doubled $doubled icon.png --out icon.iconset/icon_${size}x${size}@2x.png
done
iconutil -c icns icon.iconset && rm -rf icon.iconset

# .ico (Windows)
npx --yes png-to-ico icon.png > icon.ico
```

Replace the source PNG with a proper `1024x1024` square asset for production
quality icons (current is a stop-gap — brand mark centered on dark background).
